# 美美沙龙 · 重做设计文档

目标：画面品质、动画密度、玩法流程和选项丰富度对齐 Bimi Boo Beauty Salon 这一档的学前美容沙龙游戏。
人物、道具、界面全部原创，不复制对方的角色、美术和 UI 资源；对齐的是品类惯例和完成度。

## 0. 现状差距（为什么不在一个水平）

| 维度 | 旧版 | 目标 |
|---|---|---|
| 美术 | 代码手拼 SVG 基本形，无体积、无高光，人物像简笔画 | 专业插画级扁平矢量：同色系深色描边、柔和阴影、高光、材质 |
| 人物 | 一个 Zoey 拼装，表情靠换几条线 | 分层角色：眼睛（睁/眨/闭/笑/惊）、嘴（微笑/大笑/O/嫌弃/委屈）、眉、头发前后层，随操作实时反应 |
| 动效 | 整块平移/缩放/淡入 | 工具有使用动画（剪刀开合、吹风机出风、海绵挤压），角色有呼吸、眨眼、躲闪、痒得扭动；粒子（泡沫、水珠、蒸汽、闪粉）带物理 |
| 流程 | 每房 3–6 步，选项 3–6 个 | 前段“清洁/修复”线性 5–7 步，后段“自由装扮”多页签，每页签 6–12 个选项 |
| 反馈 | 少量 sfx + 星星 | 每一下都有反应：音效、粒子、角色表情、台词；阶段完成有小庆祝；结尾拍照 |

## 1. 总体结构

```
首页 ──「美美沙龙」大门卡 ──> 沙龙大厅（Lobby）
                               ├─ 左：5 张房间卡（可横滑），完成打勾
                               ├─ 右：展台上的当前客人（呼吸、眨眼、点她会笑/挥手）
                               └─ 展台下：换客人 · 放大看 · 拍照 · 重新打扮
房间：SPA 洗脸 / 美发 / 化妆 / 美甲 / 换装
```

- 宠物澡堂（`spa.js`）不属于美容沙龙，移回“照顾小动物”那一组。
- 客人 6 位，每位的妆发、服装跨房间保留（`store.data.salon2.looks[i]`；旧版 `salon` 存档不再读取）。
- 房间通用骨架（与对标一致）：左上 Home、右侧竖排道具栏 + 分类页签、右下（或左下）绿色对勾“完成”。
- 无失败、无计时；线性阶段用“白色虚线圈 + 指引小手 + 只亮下一件工具”引导；自由阶段随时可点对勾结束。
- 完成 = 拍照（闪光 + 相片掉落 + 礼花）→ 回大厅时客人身上带着新造型，房间卡打勾，星星 +1。

### 2.2 主持人

Zoey 只出声音（台词旁白），沙龙房间里不出现扁平小人，避免两种画风混在一起。大厅里也是客人站展台。

## 3. 五个房间

每个房间写：流程 · 每步交互 · 动效 · 台词 · 选项。

台词 key 前缀：`sl-`（新录），已有可复用的标注“复用”。

> 实现说明：Zoey 的声线是英文，所以所有台词按下表的意思写成英文短句录制（`tools/playground/voice-lines.json`，`sl-*` 共 42 句），中文仅作脚本说明。

### 3.1 SPA 洗脸（facial）

开场：客人脸上有泥点 4–6 处、小痘痘 3 个、黑眼圈，表情 sad。台词 `sl-spa-hi`「哎呀，她的小脸脏脏的，我们来帮她洗干净吧！」

| 步 | 工具 | 交互 | 动效 / 反馈 | 台词 |
|---|---|---|---|---|
| 1 洗脸 | 洗面奶瓶 → 海绵 | 拖瓶到脸上挤一坨，再拿海绵来回擦 | 瓶身挤压回弹，奶油挤出拉丝；海绵擦过起泡沫（泡泡数量随擦拭累积、会轻微晃动），泥点随擦拭渐隐；客人 giggle 扭动 | `sl-spa-wash`「挤一点洗面奶，用海绵擦一擦～」 |
| 2 冲水 | 花洒 | 拖花洒扫过泡沫 | 水线粒子 + 溅射水珠；泡沫被冲走滑落；客人 shut | `sl-spa-rinse`「哗啦啦，冲干净啦！」 |
| 3 擦干 | 毛巾 | 拖毛巾轻拍 | 毛巾按压形变，水珠被吸走 | `sl-spa-towel`「用毛巾轻轻擦干。」 |
| 4 痘痘贴 | 痘痘贴（4 款：星星/爱心/小花/云朵） | 选一款，拖到虚线圈里的痘痘上，可贴多个 | 贴上时 squash 动画 + 小闪光；痘痘被盖住后变小消失 | `sl-spa-patch`「把小痘痘贴上可爱的贴纸。」 |
| 5 调面膜 | 碗 + 食材 8 种（草莓、黄瓜、柠檬、牛油果、蓝莓、玫瑰、蜂蜜、燕麦） | 拖 2–4 种进碗，出现勺子后画圈搅拌 | 食材落碗溅起，碗里色块随搅拌旋转融合成混合色，冒小爱心 | `sl-spa-mix`「选几样喜欢的放进碗里，搅一搅！」 |
| 6 敷面膜 | 刷子（蘸碗里的颜色） | 在脸部虚线区内涂抹，覆盖 80% 自动补满 | 笔刷有湿润高光；客人 shut | `sl-spa-mask`「把面膜均匀地刷在脸上。」 |
| 7 黄瓜片 | 黄瓜片 ×2 | 拖到两只眼睛上 | 吸附动画，客人放松地哼一声；背景舒缓音乐，计时 3 s 后小闹钟响 | `sl-spa-relax`「放上黄瓜片，休息一下～」 |
| 8 卸面膜 | 湿棉片 | 擦去面膜 | 面膜卷边剥落，露出发光皮肤（闪光扫过）；客人 love | `sl-spa-glow`「哇，小脸亮晶晶的！」 |
| 9 护肤 | 面霜（4 色：粉/白/绿/金）＋ 棉片 | 点挤面霜、棉片抹匀 | 光泽层渐显 | `sl-spa-cream`「最后抹上香香的面霜。」 |

自由收尾：可再选 **眼罩/发带**（6 款）给客人戴上；对勾 → 拍照。

## 4. 大厅（Lobby）

- 背景：原创沙龙内景（镜台、灯泡化妆镜、植物、彩色瓶罐），柔和渐变+高光。
- 客人展台：呼吸 + 眨眼；点她：随机一个反应（挥手 / 转圈 / 笑出声 + 台词）。
- 换客人：当前客人走下展台（弹跳步伐）→ 新客人走上来挥手；名字气泡。
- 放大：镜头推近到脸（scale 2.1，原点在头部），再点回到全身。
- 拍照：闪光 + 拍立得相片掉落（带当前完整造型），4 s 或点击收起。
- 重新打扮：大海绵扫过，客人恢复初始造型。
- 房间卡：大图标 + 完成打勾；星星 n/5。

## 5. 通用音效与台词

- 音效沿用 `audio.js` 合成音色，新增：`squeeze`（挤瓶）、`snip`（剪刀）、`spray`（喷雾）、`blow`（吹风机循环）、`brush`（刷子沙沙）、`pop-bubble`、`clip`（指甲钳）、`giggle`（笑声，可用 TTS 生成）。
- 台词统一用 Zoey 声线（`tools/playground/voice-lines.json` + Qwen3-TTS），新录约 45 句（见各房间表）。

## 6. 技术方案

### 6.1 选型

| 方案 | 结论 |
|---|---|
| 继续手写 SVG | 否：画不到插画级，是这次差距的根源 |
| PixiJS v8（WebGL） | 否：820 KB 依赖；需要的 MeshRope/滤镜在下面的遮罩方案里用不上 |
| **位图分层 + DOM 变换 + Canvas 遮罩/涂抹** | **采用**：美术用 Codex（gpt-image）生成的插画；角色和道具是叠放的 `<img>`，动画走 WAAPI（GPU 合成）；所有“涂上去 / 擦掉 / 剪掉 / 染色”的东西是 `<canvas>` 图层，用合成模式做遮罩。现有 `Game`（拖拽、rub、toolbox、spray、pointer、win）和无头测试全部沿用 |

### 6.2 美术生产管线

1. **母版**：每类角色先出一张母版（光头半身、手、无头全身），后续所有图层都在母版上“改图”生成。
2. **改图 → 差分抠层**：Codex 以母版为输入改一处（换发型、加头饰、闭眼、穿裙子），`salon-art.py diff` 把改动的像素抠出来成为透明图层，天然与母版对齐。
3. **局部补丁**：表情（闭眼、笑眼、O 嘴…）用 `salon-art.py patch` 取改图的一个矩形、羽化边缘，叠在母版对应位置。
4. **道具表**：同类道具一张图画 6–12 个（网格、互不接触），`salon-art.py slice` 按连通域切成单个文件。
5. **肤色**：只画一个肤色，`salon-art.py skin` 把肤色族像素按明暗比例映射到另外 5 个肤色，所有发型/服装对每位客人都合身。
6. **打包**：`salon-art.py pack` 裁边 + 缩放 + 转 WebP，输出每层在母版坐标里的位置，汇总成 `js/salon/manifest.js`。
7. 生成作业清单在 `tools/playground/salon-art-jobs.json`，`salon-gen.py` 并发调用本地 `codex exec`；原图放 `.salon-art/`（不入库）。

### 6.3 运行时模块（`static/kids-playground/js/salon/`）

| 模块 | 职责 |

### 10.2 美术管线补充

- **Codex（核心图）**：母版、发型、表情、服装、道具表、背景，全部由 `salon-gen.py` 调 `codex exec` 生成（约 120 张）。
- **抠图清理**：生成图的透明通道有雾边和色点。`clean_alpha` 只保留 alpha > 235 的实心主体（开运算、去小连通域），再加 3 px 抗锯齿边。主体内部被阈值打出的小洞（< 120 px）补上，大洞（戒指、手链中间）保持透明。
- **鞋子**：10 条连衣裙改图都自带鞋，`salon-build.py` 在脚踝处（裙摆与鞋之间最后一条空行）切开，鞋子成为独立的一组。
- **全身客人的头**：全身母版自带一个光头，运行时用渐变遮罩把它在下巴下方淡出。半身像（带发型、妆容、贴纸、发饰）缩小 0.7 倍，下巴对齐到全身的下巴，并在下巴下方淡出。这就是 `js/salon/doll.js` 的 `Doll`，换装、大厅、首页大门卡、拍立得都用它。
- **换肤**：`reskin` 先按肤色色度匹配换肤色，再把暖色描边按新旧肤色的亮度比压暗（眼睛区域除外），深肤色客人的轮廓不会泛橙光。
- **本地生成（mflux）**：不复杂的图，或已有参考风格的简单改图，用本地 [mflux](https://github.com/mflux-community/mflux)（Apple Silicon 上的 MLX），省去 Codex 的排队。
  - 模型：**FLUX.2 klein 4B**（Apache-2.0，不需要 HF 授权）。它是 mflux 里最小、带编辑和多参考图的模型，`-q 8` 在 36 GB 的 M3 Pro 上跑得动。
  - 安装：`uv tool install --native-tls --python 3.13 mflux`。
  - 公司网络有 TLS 代理，下载需要先导出系统钥匙串证书，并关掉 Xet 走普通 HTTPS：
    ```sh
    security find-certificate -a -p /Library/Keychains/System.keychain /System/Library/Keychains/SystemRootCertificates.keychain > .salon-art/mflux/ca.pem
    export SSL_CERT_FILE=$PWD/.salon-art/mflux/ca.pem REQUESTS_CA_BUNDLE=$SSL_CERT_FILE HF_HUB_DISABLE_XET=1
    mflux-generate-flux2-edit -m flux2-klein-4b -q 8 --image-paths <参考图> --prompt "<改什么>" --steps 4 --seed 7 --output .salon-art/mflux/<名字>.png
    ```
  - 分工：新角色母版、成套服装、背景这类“核心图”仍交给 Codex；道具换色或换形、图标、给已有道具补一个同风格变体，用 mflux。
  - 实测：模型缓存后，512 px、4 步的一次改图约 24 s，峰值内存 8.8 GB；首次下载约 16 GB。
  - 入库：输出放在 `.salon-art/mflux/`，在 `salon-build.py` 的 `LOCAL` 表里登记。构建时去掉连到边框的白底，打包进 `PROPS`。第一张是美甲店卡片上的粉色甲油（由透明甲油瓶改色）。

### 10.3 第二轮打磨：每个动作都看得见、每件道具都像真的

- **看得见的变化**：剪过的指甲留一圈白色锯齿断口，锉刀磨平；护甲油是一滴油落下、指甲泛出琥珀色光泽；面霜先在脸上留几坨白色霜（盖在五官之上，落到眼睛上她会闭眼），抹开后变成光泽。
- **拟真的道具**：选色用带颜色的瓶子/罐子（甲油瓶、眼影盒、腮红盒、口红、唇彩、睫毛膏、染发剂、闪粉），拖出来的是沾了颜色的刷子或棒。产品图用 `productTint` 按需重染（`room.js` 的 `products()` / `productArt()`）；产品图缺失时用旧道具图加色点。
- **戴上的效果**：戒指拖到哪根手指就戴在那根手指上（`HAND.fingers`：由指甲主轴推出的戴戒位置和指宽），手链拖到手腕（`HAND.wrist`）。有 Codex 画好的“戴上”图时用它；没有时运行时画一个金戒圈 + 宝石、侧看的手链（远端一半藏在手腕后）。
- **换装**：帽子按头型给出宽度、下沿和倾角，戴帽子时藏起头顶的发饰；手持物放在手的下面一层（`held`），手指压在杆、绳、提手上。Codex 的“戴帽子/握着”图到位后自动替换，并用 keep 遮罩藏住被盖住的头发或张开的手指。翅膀、披风在货架上显示完整的一件（`icon-back-*`），穿上也是完整的一件放在身体后面（见 10.6）。
- **服装杂线**：`no_threads` 在差分遮罩上去掉细线后，再在成品图的 alpha 上跑一遍（补洞会把描边连到衣服上）。所有衣服用同一条规则，没有按单件调的特例（见 10.6）。
- **拍照**：美甲拍整只手；每个房间重玩时，这个房间改过的部分清空重来（`clearZone`）。

### 10.4 管线第三轮：更清晰、自检、mflux 优先

- **选型复核**：
  - 运行时仍然零依赖，不引入 PixiJS。最重的一步是换肤色（`reskin`），一张约 16–18 ms；按颜色重染一件产品（`productTint`）约 3–8 ms。都只在换人、选色时跑一次，用不上 WebGL。
  - **vtracer（位图转矢量）不采用**：
    - 默认参数会丢掉明暗和高光；
    - 细节参数会生成上千条路径，文件比 WebP 大 5–50 倍（gzip 之后也是）；
    - 矢量图运行时也没法用像素遮罩做涂抹和擦除。
- **超分（SeedVR2）**：`salon-upscale.py` 用 mflux 自带的 SeedVR2 3B（`-q 8`），把会大面积显示的原图放大 1.5 倍，输出到 `.salon-art/hires/`。
  - 放大的范围：母版、表情、眉毛、发型、服装、戴上的饰品、背景。
  - 放大前先把透明处填成最近的实色，避免边缘出现白边或黑边。每张图记下原图的 sha1，原图没变就跳过。
  - 速度：每张 1254 px 的图约 90 s，峰值 15.5 GB。
  - 没有用 FLUX.2 klein 来放大：它会重画整张图，颜色偏、描边变深。SeedVR2 只锐化，不改画面。
  - `salon-build.py` 用法：如果有和原图一致的放大版，颜色从放大版取，透明通道仍由原图放大得到，所以抠图结果不变。
    - 文件按 1.5 倍分辨率保存；manifest 里的坐标仍按母版单位，运行时不用改。
    - 背景改为 2400 px 宽。
    - 换肤按“每母版单位多少像素”（`k`）缩放。
- **构建自检**：每次 `salon-build.py` 都把各组图拼成棋盘底的审查图，放在 `.salon-art/review/<组>.png`，检测到的杂线标成洋红色。
  - 描边色的游离碎片超过 150 px 的，写进 `warnings.txt`，并在终端打印。
  - 想跳过就加 `--no-review`。
  - 清理规则：
    - `no_outline_strays`：反复去掉描边色的细碎片。
    - 戒指、手链、帽子用 `solo`：只保留主体附近的连通块。
    - 长指甲尖只保留指甲本身，加上 10 px 的边，不带手指轮廓。
- **混合生成（`salon-gen.py`）**：默认 `--engine auto`。先用本地 mflux（FLUX.2 klein）生成，过不了自动检查就交给 Codex。背景图和新角色母版直接交给 Codex。
  - 改图：在绿幕上生成，抠掉绿色后和原图做差分，只把变化区域羽化贴回。三条检查：
    - 变化区域占主体的比例在 0.2%–60% 之间；
    - 变化区域以外的中位色差 ≤ 12；
    - 黑色描边占比 ≤ 30%。
  - 道具表：白底加参考图生成。检查件数是否等于提示词里写的“行 × 列”，以及黑色描边占比。
  - 作业哈希存在 `<输出>.job.json`，包括提示词、输入图和风格。提示词改了才重画；`--try DIR` 只试画，不写哈希。
  - Codex 额度用完时，从报错里读出恢复时间，等到那时再重试，最多 3 次。GPU 同一时间只跑一张图。
  - klein 改图有三个系统性偏差，比较前先纠正：
    1. 绿幕会画成青绿色：按画面边框的实际颜色抠底，只有连到边框的才算背景，绿色裙子不会被抠掉。
    2. 人物整体略微放大或移位：用剪影做相位相关，在 0.9–1.1 倍之间找重叠最好的缩放和平移。如果对齐后反而更差，就不对齐。
    3. 整体偏色（每个通道差 10–25 级）：在两张图一致的像素上，逐通道拟合增益和偏移，把颜色校正回原图。
  - “改了多少”的上限按类别设定，约为 Codex 同类已采用改图最大值的 1.25–1.5 倍：戒指 5%、手链 5.5%、帽子 33%、手持物 30%、上衣 25%、下装 37%、连衣裙 60%、翅膀和披风 47%。单个作业可以用 `max_change` 覆盖。
  - 2026-11 试跑结果：
    - 宝石道具表用 mflux 一次通过，8 件，没有黑描边。
    - 珍珠手链、贝雷帽、派对裙三张改图都没过，转交 Codex。
      - klein 画手链时把指甲改了色，还在拇指上多画了一圈珍珠；
      - 画贝雷帽时眼睛也被改了色；
      - 画裙子时改动范围是身体的 104%。
    - 这和肉眼判断一致：道具表、小道具交给 mflux，贴合身体的改图仍以 Codex 为主。
  - 试跑时 mflux 的原图保存在 `<DIR>/raw/`。加 `MFLUX_REUSE=1` 可以不重画，只用新的检查规则重新判一遍。
- **美甲**：去掉单指甲放大，整只手固定。`EVERY=1` 时，美甲用例把 8 款戒指各戴到 5 根手指上并截图，用来检查每款戒指的效果。

### 10.5 参考 OpenGame 的管线改进（2026-11）

参考了 [nexu-io/opengame](https://github.com/nexu-io/opengame)。它的素材管线大部分写在给 agent 的 Markdown 技能说明里，真正有代码的部分是：素材库、能力注册表、联系表（contact sheet）、试玩测试，以及 `library/design/skills/hatch-pet` 这个确定性的精灵图集脚本。它的 76 个模板游戏都是编译后的包，没有生成源码，只借鉴方法，不用它的任何美术或代码。

**采用了的：**

| OpenGame 的做法 | 我们的实现 |
|---|---|
| 抠图底色自动选（hatch-pet `choose_chroma_key`：候选色里离主体像素最远的那个，按 1% 分位距离算） | `salon-gen.py` 的 `key_colour`：在绿、品红、青、蓝、黄里选。手选青色，头像和全身选蓝色，美人鱼裙选品红 |
| 切图时吸收碎片（`extract_strip_frames`：够大的块当种子，小碎片并到最近的种子，极小的才当噪点） | 新增共享模块 `tools/playground/salonart.py` 的 `slice_items`。`salon-build.py` 切道具表和 `salon-gen.py` 检查道具表用同一个函数，生成时数出的“8 件”就是构建切出来的 8 张；碰到表格边缘的单品会报警告（可能被裁掉） |
| “在提示词里修，不在后期修”：禁止画抠图后留不住的效果（漂浮的闪光、光晕、地面投影） | 改图和道具表的提示词都附加 `RULES`。它不算进作业哈希，改规则不会重画已经完成的图 |
| 生成后自动检查，失败就把原因写进提示词重画，最多重试 2 次，都不过就取最好的一张（`queue_pet_repairs.py`） | Codex 的图也过同一套检查（`judge`）。不过就把原因加进提示词重画，最多再画 2 次；还不过就保留最好的一张，标记“NEEDS A LOOK” |
| 不可变的版本库：每个版本记 SHA-256、提示词、模型、参数、父版本，改图出新版本，从不覆盖 | 重画前旧图和它的记录先存进 `.salon-art/versions/<路径>/<时间>-<sha8>.png`。`.job.json` 记哈希、引擎、尝试过程、sha256、时间、提示词和输入 |
| 联系表用中性灰底 `#8c8c94`（透明抠图和带底框的图一眼能分开） | `salonart.contact_sheet` 统一用灰底，白色道具（翅膀、化妆棉、碗、珍珠）也能看清。另外写出 `review.json`，每张图的尺寸、实心像素、细碎片、描边色碎片都有记录，方便以后用视觉模型批量审 |
| “不许为了通过而放宽阈值”（anti-reward-hacking） | 写进 `salon-gen.py` 说明。阈值是按 Codex 已采用的图标定的：100 张成品里误判 0 张。 <br> 标定过程中改的都是检查本身的错，没有放宽标准： <br> - 海军蓝描边不算黑描边； <br> - 只修了细条的修补作业也算“有改动”； <br> - 发型可以改到 130%； <br> - 宽檐草帽在作业里单独写了 `max_change` |
| 混音电平目标（人声最响，峰值留余量） | 语音新增 `tools/playground/voice_level.py`：按说话部分的 RMS 统一到 −19.5 dBFS，峰值不超过 −1 dBFS。`build-voice.py` 生成新片段时自动拉平。已发布的 284 条里有 48 条偏差超过 2 dB（最大的是 `wd-fox`，偏响 7 dB），`level-voice.py --apply` 只重编码这 48 条 |

**顺手修掉的问题：** 同一个输出有两个作业时（原作业，加一个后来的修补作业，比如美人鱼裙），原来会因为哈希对不上把修补结果重画掉。现在同一张图只认最后一个作业。

**没有采用的：**

| OpenGame 的做法 | 不采用的原因 |
|---|---|
| 视频转精灵图的帧动画（图生视频 → 抽帧 → 按所有帧的并集框裁切） | 我们的人物动画是分层加 WAAPI 补间，不需要逐帧图 |
| 按能力路由模型、云端付费额度 | 我们只有本地 mflux 和 Codex 两个引擎 |
| 3D 资产相关做法 | 我们没有 3D |

如果以后要做逐帧动画（比如客人走路），再按它的 `game-2d-animation.md` 来做：给每条提示词加锁定镜头、锁定朝向、只做这个动作的负面约束；按所有帧的并集框裁切并底部居中；循环动画去掉最后一帧。

### 10.6 拆分物料的规则（2026-11 第四轮）

起因：蝴蝶翅膀残破，美人鱼裙上留着头顶的弧线、手臂描边，腰两侧还露出白背心。根子都在“改图减母版”的差分抠图。改成按物件放在哪一层来定拆法：

| 物件 | 在哪一层 | 怎么拆 |
|---|---|---|
| 翅膀、披风 | 最底层（`back`，在身体后面） | 不用差分，直接用道具表里的完整物件（`props/backs.png`）。`fit_whole` 在全分辨率下搜索缩放和平移，对齐改图里露在身体两侧的部分。身体自然挡住中间。只有盖在身体上的部分（披风在肩上的系结）单独成一层 `front`，放在衣服之上、头之下（新槽位 `neck`） |
| 衣服、鞋 | 身体之上 | 差分抠图后用 `drop_redrawn` 去掉“身体被重画了一遍”的像素：与母版同一处 3 px 内的皮肤或描边同色，且母版那里是身体或空白（不是背心、短裤）。只去边缘的，衣服内部接近肤色的阴影保留 |
| 衣服盖住的旧衣服 | — | `clothes_regions` 从母版找出背心和短裤（不是肤色的最大一块，腰线是阴影最多的那一行）。连衣裙把改图在背心和短裤范围内的像素全部算作自己的，哪怕颜色和旧衣服一样（白纱裙盖白短裤），所以裙摆下不会露出短裤的边线（芭蕾裙、毛衣裙的“残余边线”就是这样来的）。上衣和下装只换一半：改图里没变的像素（另一半的背心、短裤，腰线上的一条白边）不算自己的；旁边没变的旧短裤边（比短裤瘦的牛仔裤两侧）用 `body_keep` 藏起来 |
| 帽子 | 头像之上 | 同衣服 |
| 手持物 | 衣服之上（`hand`） | 握拳是画在原来张开的手上的新皮肤，是成块的形状，保留。胳膊在新姿势里挪了几像素，留下细条的皮肤和描边：离成块形状（开运算 9 px）远的肤色、描边色像素去掉，否则它们画在衣服之上，会在袖子上划出线。气球绳、棒棒糖棍不是肤色，保留；差分里被开运算去掉的细绳由 `strings` 补回（连着物件、不是肤色的新细线）。最后去掉 400 px 以下的游离碎片 |
| 比背心窄的衣服 | — | `body_keep` 给身体图做遮罩：改图里是背景、母版里却有东西的地方，穿上时藏起来。腰两侧的白背心就这样消失。人鱼、芭蕾、仙子、公主、彩虹裙都有这个问题，现在都修了 |
| 手持物的张开手指 | — | 同一个 `body_keep`，范围放大到 110 px，指尖也藏住 |

运行时：`Doll.mask` 改成每个物件各有自己的遮罩（`owner`），几个遮罩取交集（`mask-composite: intersect`）。穿着修身裙、手里拿着气球，两张遮罩同时生效。

去掉了按单件衣服手调的特例：原来水手服、人鱼裙的 `no_threads` 半径是 8，它把盖住背心的细条皮肤也吃掉了。现在所有衣服都用同一条规则。

### 10.7 测试

`tools/playground/test.mjs` 里，每个房间都有完整试玩用例：

- 线性段每一步都断言真的发生了（覆盖率、泡沫、发长、遮罩像素）。
- 自由段每个页签都用到；换装把每个页签的每个选项都穿一遍。
- 大厅用例：画廊里 6 位客人都画出来、选中后换人、放大、拍照、重置、进房间再回来。
- 美甲用例：戒指拖到指定手指（`__salon.fingerPoint`）、手链拖到手腕，检查 `__salon.worn()`。`EVERY=1` 时换装用例给每个选项截图。
- “look” 用例检查回到大厅后造型保留、房间打勾。
